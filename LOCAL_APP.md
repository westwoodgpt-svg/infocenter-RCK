# Локальное приложение Битрикс24 «Инфоцентр РЦК» — что известно

Сводка собрана из репозитория (`README.md`, `DEPLOYMENT.md`, код `api/` и `src/`)
по состоянию на 01.10.2026. Здесь только то, что подтверждается кодом или
документацией; неясные места вынесены в конец.

## Что это

- Редактируемый дашборд (инфоцентр) для Регионального центра компетенций (РЦК)
  ЦПП Калининградской области: React 19 + Vite 6 + TypeScript + Tailwind 4 +
  Recharts, импорт таблиц через SheetJS (`xlsx`).
- Встроен в Битрикс24 как **локальное приложение** — открывается в iframe
  портала из пункта меню.
- Одно приложение обслуживает **инфоцентры всех отделов** из структуры портала:
  сотрудник сразу попадает в инфоцентр своего отдела.
- 5 вкладок: Безопасность, Качество, Производство, Затраты, Персонал.
- Карточки вводятся вручную в «Режиме редактирования». Интеграция со Списками
  Битрикс24 (11 списков, ID 78–87) удалена 07.08.2026; данные, которые оттуда
  приходили (на 09.07.2026), лежат стартовым набором в `src/seedData.ts`.

## Регистрация в Битрикс24

Приложения → Разработчикам → Другое → **Локальное приложение**:

| Параметр | Значение |
|---|---|
| Путь обработчика | URL проекта на Vercel (в коде упоминается `https://infocenter-rck.vercel.app`) |
| Права (scope) | `user` («Пользователи») и `department` («Структура компании»); `lists` больше не нужен |
| «Использует только API» | выключено |
| BitrixMobile | выключено |
| Пункт меню | закрепить звёздочкой «В избранное» — иначе уходит в конец «Ещё» |
| Ключи | «Ключ приложения» (client_id) и «Секретный ключ» (client_secret) → переменные `BITRIX_CLIENT_ID` / `BITRIX_CLIENT_SECRET` на Vercel |

Без `user`/`department` инфоцентры по отделам не включаются: все видят общий
инфоцентр РЦК и предупреждение в шапке. Без `user` также не работает
автоподстановка ФИО/фото/должности в карточке «Ответственный» (`user.get`).

Пример REST-адреса портала в комментариях кода — `https://portal39.mb-product.ru/rest/`
(`api/_bitrixAuth.js`), то есть портал, судя по всему, коробочный/на своём домене.

## Как приложение открывается

1. Битрикс24 открывает обработчик **POST-запросом**, передавая в теле
   `AUTH_ID`/`REFRESH_ID` и прочие параметры открывшего пользователя.
2. Обычная статика Vercel (и GitHub Pages) отвечает на POST `405`, поэтому весь
   не-API трафик идёт в serverless-функцию `api/serve.js`, которая отдаёт
   файлы `dist/` на любой HTTP-метод (маршруты — в `vercel.json`).
3. На POST `serve.js` вызывает `maybeCaptureServiceToken` (`api/_bitrixAuth.js`):
   если открыл администратор портала, его `REFRESH_ID` обменивается через
   `https://oauth.bitrix.info/oauth/token/` на сервисный токен, который
   сохраняется в Redis (`rck:bx-service-token`) и дальше обновляется по
   `refresh_token`.
4. `index.html` подключает SDK `https://api.bitrix24.com/api/v1/` **только внутри
   iframe** (`window.self !== window.top`). Вне портала (прямой заход,
   `npm run dev`) приложение работает в **автономном режиме** на `localStorage`.

Нюанс из кода: в install/open-POST этого приложения `client_endpoint` не
приходит, только `SERVER_ENDPOINT` (адрес сервера авторизации, а не портала),
поэтому адрес REST портала берётся из ответа `oauth.token`.

## Использование REST API Битрикс24

| Метод | Кто вызывает | Зачем |
|---|---|---|
| `profile` | сервер, токеном сотрудника | проверка, что запрос идёт из действующей сессии портала |
| `user.current` | сервер, токеном сотрудника | `UF_DEPARTMENT` — отделы сотрудника |
| `department.get` | сервер, сервисным токеном | дерево отделов и руководители (`UF_HEAD`) |
| `user.get` | браузер (`BX24.callMethod`) | автоподстановка в карточке «Ответственный» |
| `app.option.get` | браузер / сервер | запасное чтение и разовый перенос старых данных |
| `app.option.set` | сервер, сервисным токеном | резервная копия (ключ `rck_dashboard_v1`, пока данные ≤ ~48 КБ) |

`app.option.set` разрешён только администраторам портала — поэтому браузер
сотрудника сам в портал не пишет; запись идёт через свой сервер.

Токен сотрудника берётся из `BX24.getAuth()`; если он прожил больше часа —
обновляется через `BX24.refreshAuth`, и запрос повторяется.

## Серверная часть (Vercel)

Хостинг — Vercel, автодеплой при пуше в `main` репозитория
`westwoodgpt-svg/infocenter-RCK`. Сборка: `npm run build` → `dist/`.

| Эндпоинт | Назначение |
|---|---|
| `POST /api/dashboard` | основной API; действия `bootstrap`, `load`, `save`, `history`, `summary`, `summary-config`, `summary-config-save` |
| `POST /api/save-dashboard` | старый эндпоинт записи — оставлен для вкладок со старым бандлом |
| `GET /api/bitrix-status` | диагностика (без раскрытия токена): задеплоенный коммит, наличие `REDIS_URL` и ключей, состояние сервисного токена, видимость структуры отделов (`departments`, `departmentsError`), результат разовой копии (`legacyCopy`) |
| всё остальное | `api/serve.js` — раздача `dist/` |

### Хранилище — Redis

Подключается через Vercel Marketplace (`REDIS_URL`, клиент `ioredis`).
Рекомендуется переиспользовать базу infocenter-IIC — ключи разведены префиксами
(`rck:` против `iic:`). Предел — 3,5 МБ на инфоцентр.

Основные ключи:

- `rck:board:<id>:current` — состояние инфоцентра отдела;
- `rck:dashboard:current`, `rck:dashboard:snap:<rev>` — исторический общий
  инфоцентр РЦК и снимки для слияния (живут сутки);
- `rck:card-history:...` — история карточек (до ~40 версий, ~700 КБ на карточку);
- `rck:summary-config:<id сотрудника>` — личная настройка сводного экрана;
- `rck:legacy-copy:<инфоцентр>` — отметка о разовой копии РЦК отделу;
- `rck:bx-service-token`, `rck:bx-last-open` — сервисный токен и диагностика открытия.

### Переменные окружения

Обязательные: `REDIS_URL`, `BITRIX_CLIENT_ID`, `BITRIX_CLIENT_SECRET`.

Необязательные: `INFOCENTER_LEGACY_DEPARTMENT_ID`, `INFOCENTER_HIDDEN_DEPARTMENTS`,
`INFOCENTER_DIRECTOR_IDS`, `INFOCENTER_RCK_COPY_DEPARTMENT_ID`,
`INFOCENTER_RCK_COPY_DEPARTMENT_NAME`, `INFOCENTER_RCK_COPY_OVERWRITE`.

После первой настройки администратор портала должен **один раз полностью
открыть приложение** — тогда сервер получит сервисный токен. На сохранение
карточек сотрудниками это уже не влияет (нужно только для переноса из
`app.option` и резервной копии).

## Доступ и инфоцентры отделов

Решает сервер (`api/_access.js`); ID инфоцентра из запроса всегда сверяется со
списком доступных.

| Кто | Видит | Правит |
|---|---|---|
| Сотрудник | свои отделы и вышестоящие | свои отделы |
| Руководитель (`UF_HEAD`) | свой отдел и подотделы | свой отдел и подотделы |
| Директор (глава корневого отдела или из `INFOCENTER_DIRECTOR_IDS`) | всё | всё |
| Администратор портала | всё | всё |

- У кого доступно больше одного инфоцентра — переключатель в шапке и **сводный
  экран** (одна вкладка по всем отделам, только просмотр, с личной настройкой).
- Если структура отделов недоступна — все получают общий инфоцентр РЦК
  с предупреждением, никто не заперт.
- Исторические данные РЦК — инфоцентр «РЦК (общий)», пока не задан
  `INFOCENTER_LEGACY_DEPARTMENT_ID`. С 07.09.2026 они ещё и разово скопированы
  отделу «Региональный центр компетенций в сфере производительности труда»
  (`api/_seedCopy.js`), исходник не тронут.

## Сохранение и синхронизация

- Бейдж в шапке: «Общие данные Битрикс24» (зелёный) или «Автономный режим
  (только этот браузер)» (серый).
- Сохранение с debounce 500 мс, повтор с нарастающей паузой при ошибке; правки
  не теряются и остаются в браузере до успешной отправки.
- Правки двух вкладок сливаются по карточкам (трёхстороннее слияние по `baseRev`).
- Подтягивание изменений коллег — кнопка «Обновить», при возврате на вкладку и
  примерно раз в минуту; пока есть несохранённые правки, чтение не затирает их.
- Картинки ужимаются в браузере (до 1600 px, JPEG).

## Карточки (кратко)

KPI, График (столбцы/линии/области/круговой, комбо), Смета, Список,
Ответственный, Событие, Список событий (счётчики дней), Таблица (импорт
.xlsx/.xls/.csv с выбором листа, строки заголовков, объединёнными ячейками,
заливкой; ширина столбцов; значки уровней 0–4), Изображение (во весь экран).
История версий карточки — только в режиме редактирования. Экспорт/импорт всего
дашборда JSON-файлом. Подробности — в `README.md`.

## История хостинга

1. Диск Битрикс24 — не подошёл (блокирует HTML со `<script>`).
2. GitHub Pages — не подошёл (`405` на POST).
3. Cloudflare Workers — временно, затем отклонён решением пользователя.
4. **Vercel** (с 07.08.2026) — текущий, по той же схеме, что infocenter-IIC.

## Неясности и хвосты

- **Расхождение по правам**: `README.md` говорит, что дополнительный scope не
  требуется (кроме, возможно, `user`), а `DEPLOYMENT.md` и код `api/_access.js`
  требуют `user` и `department`. Актуально второе.
- **Остатки шаблона Google AI Studio**: `metadata.json` (Gemini capability),
  `.env.example` (`GEMINI_API_KEY`, `APP_URL`), зависимости `@google/genai`,
  `express`, `dotenv`, имя пакета `react-example`. В коде `src/` и `api/` они
  не используются.
- Точный домен портала и URL обработчика в репозитории не зафиксированы — только
  в комментариях (`portal39.mb-product.ru`, `infocenter-rck.vercel.app`).
- Какие права реально выданы приложению на портале и заданы ли необязательные
  переменные `INFOCENTER_*` — из репозитория не видно; проверяется на
  `/api/bitrix-status`.
