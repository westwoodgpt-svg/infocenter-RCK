# Инфоцентр РЦК

Редактируемый дашборд для Регионального центра компетенций (РЦК) ЦПП Калининградской
области — React + Vite + TypeScript + Recharts, встроен в Битрикс24 как локальное
приложение.

Раньше дашборд читал показатели напрямую из 11 Списков Битрикс24. Эта интеграция
удалена: теперь все карточки собираются вручную через редактор — по образцу
[infocenter-IIC](https://github.com/westwoodgpt-svg/infocenter-IIC), откуда сюда
перенесён конструктор карточек. Значения, которые раньше приходили из Списков
(на 09.07.2026), перенесены в `src/seedData.ts` как обычные карточки — стартовый
набор, который можно менять как любой другой.

## Редактор карточек

Включите **«Режим редактирования»** (кнопка в шапке) — на любой из 5 вкладок
(Безопасность, Качество, Производство, Затраты, Персонал) можно:

- **Добавлять / редактировать / удалять** карточки пяти типов: KPI (план/факт/%),
  График, Смета (план/факт), Список, Ответственный (с автоподстановкой ФИО/фото/
  должности из сотрудников Битрикс24).
- **Менять тип графика**: столбчатый, линейный, с областями, круговой — данные
  задаются таблицей «категория × ряды», ряды и категории можно добавлять и убирать.
- **Менять порядок карточек** стрелками вверх/вниз.
- Сбросить к восстановленным данным РЦК или очистить вкладку («⚙» в шапке).
- Экспортировать/импортировать весь дашборд JSON-файлом.

## Общие данные для всех пользователей (Битрикс24)

Приложение встраивается в Битрикс24 как локальное приложение (iframe). Внутри портала
все изменения сохраняются в общих данных приложения (`app.option` — общий JSON на
уровне приложения, один на весь портал) и видны **любому сотруднику**, открывшему
инфоцентр — не только в браузере того, кто редактировал.

- Бейдж в шапке показывает режим: «Общие данные Битрикс24» (зелёный) или «Автономный
  режим (только этот браузер)» (серый, если открыто вне портала — тогда данные живут
  в `localStorage` этого браузера).
- Кнопка «Обновить» рядом с режимом редактирования подтягивает последние изменения
  коллег; автоматически это происходит и при возврате на вкладку браузера.
- Обновления не в реальном времени: если два человека редактируют одновременно,
  сохраняется последняя версия (last-write-wins), без слияния правок.

### Почему сохраняет не только администратор

`app.option.set` в Битрикс24 разрешён только пользователям с правами администратора
портала — если бы браузер каждого сотрудника писал в `app.option` напрямую,
редактировать дашборд мог бы только админ. Поэтому запись идёт иначе:

1. Браузер отправляет изменения на `/api/save-dashboard` вместе с токеном текущего
   пользователя (`BX24.getAuth()`).
2. Сервер проверяет, что это действующая сессия портала (`profile`), и затем сам
   пишет в `app.option` — но не токеном текущего сотрудника, а отдельным
   **сервисным токеном**, изначально полученным от администратора.
3. Сервисный токен сервер получает автоматически: когда администратор портала
   открывает приложение (обычное открытие, POST от Битрикс24 с
   `AUTH_ID`/`REFRESH_ID`), сервер проверяет через `profile`, что открывший — админ,
   и сохраняет его токен как сервисный (см. [`api/_bitrixAuth.js`](api/_bitrixAuth.js),
   [`api/serve.js`](api/serve.js)). Токен обновляется автоматически через
   `refresh_token`, пока такое открытие происходит хотя бы изредка.

Чтение (`app.option.get`) не ограничено — вызывается прямо из браузера, без сервера.

Это тот же протокол и та же связка хостинга (GitHub + Vercel + Redis), что в
infocenter-IIC — см. [`DEPLOYMENT.md`](DEPLOYMENT.md) для деталей и обязательной
настройки на Vercel.

### Как подключить приложение в Битрикс24

Приложения → Разработчикам → Другое → Локальное приложение:
- Путь обработчика: URL проекта на Vercel
- Права: дополнительный scope не требуется для карточек (раньше был нужен `lists`
  для чтения Списков — теперь можно снять).
- «Использует только API» и BitrixMobile — выключены.
- Закрепить пункт меню звёздочкой «В избранное» — новые приложения уходят в конец
  списка «Ещё».
- Скопировать **«Ключ приложения»** (client_id) и **«Секретный ключ»**
  (client_secret) со страницы этого локального приложения — понадобятся для
  переменных окружения на Vercel, см. `DEPLOYMENT.md`.

## Разработка

```bash
npm install
npm run dev       # http://localhost:3000
npm run build      # сборка в dist/
npm run lint        # tsc --noEmit
```

Вне Битрикс24 (`npm run dev` в обычном браузере, не в iframe) `window.BX24` не
подключается, и приложение автоматически работает в автономном режиме на
`localStorage` — так и тестируется редактор карточек без необходимости открывать
портал.

## Деплой

Хостинг — Vercel (GitHub + Vercel, как в infocenter-IIC), автодеплой при пуше в
`main`. Обязательная разовая настройка (Redis, `BITRIX_CLIENT_ID`/
`BITRIX_CLIENT_SECRET`) — в [`DEPLOYMENT.md`](DEPLOYMENT.md).
