# Инфоцентр РЦК

Редактируемый дашборд для Регионального центра компетенций (РЦК) ЦПП Калининградской
области — React + Vite + TypeScript + Recharts, встроен в Битрикс24 как локальное
приложение.

Раньше дашборд читал показатели напрямую из 11 Списков Битрикс24. Эта интеграция
удалена: теперь все карточки собираются вручную через редактор — по образцу
[infocenter-IIC](https://github.com/westwoodgpt-svg/infocenter-IIC), откуда сюда
перенесён конструктор карточек. Значения, которые раньше приходили из Списков
(на 09.07.2026), перенесены в `src/seedData.ts` как обычные карточки — стартовый
набор, который можно менять как любой другой.

## Редактор карточек

Включите **«Режим редактирования»** (кнопка в шапке) — на любой из 5 вкладок
(Безопасность, Качество, Производство, Затраты, Персонал) можно:

- **Добавлять / редактировать / удалять** карточки: KPI (план/факт/%), График,
  Смета (план/факт), Список, Ответственный (с автоподстановкой ФИО/фото/должности
  из сотрудников Битрикс24), Событие, Список событий, Таблица (xlsx/csv),
  Изображение.
- **Считать дни по событиям** — и в одиночной карточке «Событие», и в карточке
  «Список событий»: для каждого события выбирается отсчёт до даты («через N дней»)
  или обратный счёт от даты («N дней прошло», например «дней без штрафа»).
  События без даты не пропадают из списка, а помечаются «дата не указана».
- **Выделять цветом ячейки таблицы** — заливка выбирается по ячейке (квадрат
  слева от значения), одним нажатием можно залить всю строку или столбец;
  цвета переезжают вместе с ячейками при добавлении и удалении строк и столбцов.
- **Задавать ширину столбцов таблицы** — полем в пикселях под заголовком столбца
  или перетаскиванием правой границы заголовка (двойной щелчок по границе
  возвращает ширину «по содержимому», кнопка «Ширина столбцов — авто» сбрасывает
  все сразу). Ширины переезжают вместе со столбцами при их добавлении и удалении.
- **Показывать числа 0–4 значками освоения** — «пироги» матрицы компетенций:
  0 — пустой кружок, 4 — закрашенный. Включается по столбцу (кнопка в шапке
  столбца) или сразу для всех подходящих столбцов — кнопкой «Значки 0–4» над
  таблицей. Значения вне 0–4 остаются числами, поэтому сводные строки
  («минимальное», «фактическое») не портятся.
- **Загружать таблицы из Excel** — .xlsx, .xls и .csv, см. ниже.
- **Менять тип графика**: столбчатый, линейный, с областями, круговой — данные
  задаются таблицей «категория × ряды», ряды и категории можно добавлять и убирать.
- **Менять порядок карточек** стрелками вверх/вниз.
- Сбросить к восстановленным данным РЦК или очистить вкладку («⚙» в шапке).
- Экспортировать/импортировать весь дашборд JSON-файлом.

В режиме просмотра доступно и без прав на правку:

- **Изображение во весь экран** — кнопка в углу картинки или щелчок по ней;
  закрывается щелчком по фону, крестиком или клавишей Esc.
- **Длинный текст в ячейках таблицы переносится по словам**, поэтому строка
  становится выше, а таблица не уезжает в бесконечную горизонтальную прокрутку.

## Витрина — общая информация для всех отделов

**Витрина** — один общий экран для всей компании: колонки-разделы («Для
инфостендов отделов», «Общая инфо», …) со стикерами. Открывается первым пунктом
переключателя инфоцентров в шапке.

**Что открывается при входе.** При самом первом входе — витрина. Дальше —
то, с чем сотрудник работал в прошлый раз: витрина, сводный экран или
конкретный инфоцентр. Это запоминается на портале под сотрудником
(`rck:last-view:<id>` в Redis), поэтому работает и с другого компьютера, и из
десктопа Битрикс24. Если сохранённый инфоцентр стал недоступен, открывается
витрина.

Правят витрину все сотрудники — так же, через «Режим редактирования»:

- **Колонки** добавляются, переименовываются прямо в заголовке, удаляются;
  переставляются перетаскиванием за значок ⋮⋮ или стрелками ‹ ›. Ширина
  колонки меняется перетаскиванием её правого края, двойной щелчок по краю
  возвращает ширину по умолчанию.
- **Стикеры** — цвет (жёлтый, розовый, зелёный, голубой, сиреневый,
  оранжевый, серый), необязательный заголовок в полосе сверху, текст с
  переносами строк и кликабельными ссылками. Перетаскиваются за верхнюю полосу
  внутри колонки и между колонками. Размер (ширина и высота) меняется за
  правый нижний уголок, двойной щелчок по уголку — размер по умолчанию.
- **Вложения** — картинки показываются на стикере и открываются во весь
  экран, остальные файлы (PDF, Excel, Word, …) — ссылкой «открыть» и кнопкой
  «скачать». Скриншот можно вставить в текст стикера прямо из буфера (Ctrl+V).
  Большие файлы (до 50 МБ) хранятся в Vercel Blob, см. `DEPLOYMENT.md`; пока
  хранилище не подключено, можно прикладывать файлы до 700 КБ.
- **Закрепить** — стикер идёт первым в своей колонке.
- **Актуально до** — после этой даты стикер уходит с витрины; в режиме
  редактирования он остаётся приглушённым с пометкой «срок истёк».
- **История изменений** каждого стикера — в его редакторе: версии с датой и
  автором и кнопка «Восстановить».

Хранится витрина так же, как инфоцентр отдела (`rck:board:showcase:*` в Redis):
правки двух сотрудников сливаются по стикерам и колонкам, несохранённое
остаётся в браузере и отправляется повторно. Стартовое наполнение — стикеры с
общего стенда на момент запуска (`src/showcaseSeed.ts`).

## Инфоцентр каждого отдела

Приложение одно, а инфоцентров столько, сколько отделов в структуре Битрикс24.
Сотрудник открывает пункт меню и сразу попадает в инфоцентр своего отдела —
выбирать ничего не нужно. Кому что доступно, решает сервер по данным портала:

| Кто | Что видит | Что правит |
|---|---|---|
| Сотрудник | свои отделы и вышестоящие подразделения | свои отделы |
| Руководитель отдела (`UF_HEAD`) | свой отдел и все подотделы | свой отдел и все подотделы |
| Директор (руководитель корневого отдела) | все отделы | все отделы |
| Администратор портала | все отделы | все отделы |

Переключатель инфоцентров появляется в шапке только у тех, кому доступен не
один инфоцентр. Там же — **сводный экран**: выбранная вкладка (Безопасность,
Качество, …) по всем доступным отделам сразу, с переходом в инфоцентр любого из
них. Сводный экран — только просмотр.

Кнопка **«Настроить сводку»** на сводном экране открывает редактор: руководитель
сам решает, какие отделы на него тянуть, в каком порядке они идут и какие именно
карточки брать из каждого отдела (карточки выбираются отдельно для каждой
вкладки; по умолчанию — все, и тогда новые карточки отдела появляются в сводке
сами). Настройка личная: она хранится на портале под сотрудником
(`rck:summary-config:<id>` в Redis, см. [`api/_store.js`](api/_store.js)),
переезжает с ним на другой компьютер и не меняет ни инфоцентры отделов, ни
сводку коллег.

Инфоцентр чужого отдела открывается в режиме просмотра: кнопка редактирования и
правки карточек в нём недоступны, а сервер в любом случае отклоняет запись без
прав.

Данные отделов не смешиваются: у каждого инфоцентра своё хранилище и своя
история версий карточек.

### Загрузка таблиц из Excel

Кнопка «Выбрать .xlsx / .xls / .csv» в карточке «Таблица» не подставляет файл
вслепую: сначала он разбирается (`src/tableImport.ts`), а редактор показывает,
что получилось, и даёт уточнить разбор.

- **Лист.** Видны все листы книги с числом строк — берётся выбранный, а не
  всегда первый.
- **Строка заголовков.** Определяется автоматически (самая заполненная из
  первых строк), меняется стрелками — над таблицей в файле обычно стоит шапка
  отчёта, и она не должна становиться заголовками столбцов.
- **Объединённые ячейки** размножаются на весь свой диапазон, иначе шапка
  рассыпается на пустые столбцы. Отключается галочкой.
- **Заливка ячеек Excel** переносится в палитру карточки (зелёная, жёлтая,
  красная, синяя, фиолетовая, серая); белый и «бумажный» бежевый остаются без
  заливки. Отключается галочкой.
- **Даты, проценты и числа** попадают в карточку в том виде, в каком их
  показывает Excel: `01.09.2026`, `44%`, `1 234,5` — а не сырыми `46266` и
  `0.4352941176`.
- **Перенос строки внутри ячейки** сохраняется, как и любые символы: эмодзи
  (🟢 🟠), стрелки, галочки, кавычки-ёлочки, №.
- Пустые строки и столбцы по краям листа обрезаются.

Значки-«пироги» в матрицах компетенций из файла не приходят: их рисует условное
форматирование Excel поверх чисел, в самих ячейках лежат 0–4. Зато карточка умеет
рисовать их сама — кнопка «Значки 0–4» над таблицей включает их для всех столбцов,
похожих на уровни (кнопка в шапке столбца — для одного). Проверено на матрице
компетенций РЦК: из 17 столбцов значки включились у 11 — списки ФИО, номера и
количества остались числами.

### РЦК — один инфоцентр

Отдел портала «Региональный центр компетенций в сфере производительности
труда» и есть РЦК, поэтому отдельного инфоцентра отдела у него нет: его
сотрудники и руководитель работают в **«Инфоцентре РЦК»** (данные и история —
в ключах `rck`, как и раньше). Отдел находится по названию или по
`INFOCENTER_RCK_DEPARTMENT_ID`; на `/api/bitrix-status` это видно в поле
`rckDepartment`.

Разовая копия инфоцентра РЦК отделу (`api/_seedCopy.js`, 07.09.2026)
отключена. Получившийся дубль (`rck:board:dept-115:*`) из приложения убран;
убрать его и из Redis — в архив, с отчётом о расхождениях — можно скриптом
`deploy/archive-rck-duplicate.js` (см. `deploy/README.md`).

## Общие данные для всех пользователей (Битрикс24)

Приложение встраивается в Битрикс24 как локальное приложение (iframe). Внутри портала
все изменения сохраняются в общем хранилище инфоцентра (Redis на стороне сервера, см.
[`api/_store.js`](api/_store.js)) и видны **любому сотруднику**, открывшему инфоцентр —
не только в браузере того, кто редактировал.

- Бейдж в шапке показывает режим: «Общие данные Битрикс24» (зелёный) или «Автономный
  режим (только этот браузер)» (серый, если открыто вне портала — тогда данные живут
  в `localStorage` этого браузера).
- Кнопка «Обновить» рядом с режимом редактирования подтягивает последние изменения
  коллег; автоматически это происходит при возврате на вкладку и примерно раз в минуту.
- Правки двух вкладок **сливаются по карточкам**: сервер знает, от какой версии
  отталкивалась каждая вкладка, и накладывает только её изменения — коллеги больше не
  затирают друг друга целиком.
- Если сохранить не удалось (нет сети, портал недоступен), правка остаётся в браузере,
  в шапке видно ошибку, и отправка автоматически повторяется. Ничего не пропадает.

### История изменений карточек

История — инструмент редактора, поэтому она видна только в **режиме редактирования**:
там внизу карточки появляется «История изменений» — ползунок листает сохранённые версии
именно этой карточки (дата, автор правки, кнопка «Восстановить»). Пока выбрана прошлая
версия, карточка подсвечена жёлтой рамкой и показывает содержимое той версии;
«К текущей» возвращает актуальное состояние. При выходе из режима редактирования
карточка тоже возвращается к текущей версии, чтобы на дашборде не осталась висеть
прошлая. В режиме просмотра инфоцентр показывает только сами карточки.

Внутри портала историю ведёт сервер (последние ~40 версий каждой карточки), в
автономном режиме — сам браузер (`localStorage`). Очень тяжёлые изображения в истории
не хранятся, только структура карточки.

### Почему сохраняет не только администратор

`app.option.set` в Битрикс24 разрешён только администраторам портала, поэтому запись
никогда не шла напрямую из браузера сотрудника:

1. Браузер отправляет изменения на `/api/dashboard` вместе с токеном текущего
   пользователя (`BX24.getAuth()`); токен, проживший больше часа, обновляется через
   `BX24.refreshAuth` и запрос повторяется.
2. Сервер проверяет, что это действующая сессия портала (`profile`), и пишет данные в
   Redis — своё хранилище, без ограничений Битрикс24 на объём значения опции.
3. Сервисный токен администратора (см. [`api/_bitrixAuth.js`](api/_bitrixAuth.js),
   [`api/serve.js`](api/serve.js)) теперь нужен только для двух вещей: разового
   переноса ранее внесённых данных из `app.option` и резервной копии туда же, пока
   дашборд помещается в опцию портала. На возможность сохранять он больше не влияет.

Это тот же протокол и та же связка хостинга (GitHub + Vercel + Redis), что в
infocenter-IIC — см. [`DEPLOYMENT.md`](DEPLOYMENT.md) для деталей и обязательной
настройки на Vercel.

### Как подключить приложение в Битрикс24

Приложения → Разработчикам → Другое → Локальное приложение:
- Путь обработчика: URL проекта на Vercel
- Права: дополнительный scope не требуется для карточек (раньше был нужен `lists`
  для чтения Списков — теперь можно снять). Если автоподстановка ФИО/должности/
  фото в карточке «Ответственный» не работает — этому порталу, судя по всему,
  нужен явный scope `user` (право «Пользователи») для метода `user.get`; добавьте
  его приложению и переоткройте инфоцентр. Модалка редактирования теперь сама
  подсказывает причину, если список сотрудников не подтянулся.
- «Использует только API» и BitrixMobile — выключены.
- Закрепить пункт меню звёздочкой «В избранное» — новые приложения уходят в конец
  списка «Ещё».
- Скопировать **«Ключ приложения»** (client_id) и **«Секретный ключ»**
  (client_secret) со страницы этого локального приложения — понадобятся для
  переменных окружения на Vercel, см. `DEPLOYMENT.md`.

## Разработка

```bash
npm install
npm run dev       # http://localhost:3000
npm run build      # сборка в dist/
npm run lint        # tsc --noEmit
```

Вне Битрикс24 (`npm run dev` в обычном браузере, не в iframe) `window.BX24` не
подключается, и приложение автоматически работает в автономном режиме на
`localStorage` — так и тестируется редактор карточек без необходимости открывать
портал.

## Деплой

**Свой сервер (без Vercel)** — установка одним скриптом, перенос данных из
Redis и Vercel Blob, обновление и резервные копии: [`deploy/README.md`](deploy/README.md).
Запуск локально так же, как на сервере: `npm run build && npm start`.

**Vercel** (как было):

Хостинг — Vercel (GitHub + Vercel, как в infocenter-IIC), автодеплой при пуше в
`main`. Обязательная разовая настройка (Redis, `BITRIX_CLIENT_ID`/
`BITRIX_CLIENT_SECRET`) — в [`DEPLOYMENT.md`](DEPLOYMENT.md).
