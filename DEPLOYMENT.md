# Инфоцентр РЦК — как это устроено

Дашборд для ЦПП Калининградской области (React + Vite + TypeScript + Recharts),
встроен в Битрикс24 как локальное приложение.

## Что было сделано

**14.07.2026 — первая сборка и деплой (интеграция со Списками Б24).**

1. Собрали проект (`npm install && npm run build`) — тогда дашборд ещё читал
   показатели напрямую из 11 Списков Битрикс24 (`LISTS`, ID 78–87).

2. **Починили баг с пустыми графиками.** На вкладках «Качество» и «Персонал»
   часть графиков не рисовалась (высота контейнера — 0, SVG отсутствовал).
   Причина — CSS: обёртки графиков имели класс `flex-1` внутри карточки
   `flex flex-col` без явной высоты у родителя, из-за чего `height: 100%` у
   `ResponsiveContainer` схлопывался в 0. Убрали `flex-1`, оставив `h-[...]`.

3. Добавили `base: './'` в `vite.config.ts` — пути к `assets/index.js` и
   `assets/index.css` в `dist/index.html` стали относительными (без этого
   Vite ставит абсолютные `/assets/...`, и сборка не открывается не из
   корня домена).

4. Хостинг: сначала перебрали Диск Битрикс24 (не подходит — блокирует
   HTML со `<script>`) и GitHub Pages (отвечает `405` на POST, которым
   Битрикс24 открывает локальное приложение), затем временно остановились
   на **Cloudflare Workers**.

**07.08.2026 — интеграция со Списками удалена, добавлен редактор карточек;
хостинг перенесён на Vercel.**

1. Автосинхронизация со Списками Битрикс24 (`LISTS`, `RckDashboardData`,
   `SecurityPanel`/`QualityPanel`/`ProductionPanel`/`CostsPanel`/`PersonnelPanel`,
   `src/data.ts`) полностью удалена и заменена редактируемым конструктором
   карточек, перенесённым из [infocenter-IIC](https://github.com/westwoodgpt-svg/infocenter-IIC)
   (коммит `646e2f2`) — см. `README.md` про типы карточек и UX. Показатели
   теперь вводятся вручную через «Режим редактирования», а не читаются из
   Списков.

2. **Cloudflare Workers отклонены** (решение пользователя, не техническое
   ограничение) — хостинг и бэкенд общих данных перенесены на **Vercel**, по
   той же связке, что уже работает в infocenter-IIC: serverless functions
   (`api/*.js`) + Redis (через Vercel Marketplace) для хранения сервисного
   токена администратора. `worker.js`/`wrangler.jsonc` удалены из репозитория.

## Хостинг: Vercel (GitHub + Vercel, как в infocenter-IIC)

- Репозиторий подключён к проекту Vercel; автодеплой при пуше в `main`.
- `vercel.json` — маршрутизация: `/api/save-dashboard` и `/api/bitrix-status`
  на свои serverless-функции, всё остальное — на `api/serve.js`.
- `api/serve.js` — раздаёт `dist/` для ЛЮБОГО HTTP-метода. Обычная
  статическая раздача Vercel отвечает на POST ошибкой `405`, а Битрикс24
  открывает локальное приложение именно POST-запросом (передаёт токен
  авторизации во внутренний iframe) — поэтому весь трафик идёт через
  serverless-функцию. На POST дополнительно вызывает `maybeCaptureServiceToken`
  из `_bitrixAuth.js` (см. ниже).
- Деплой при необходимости вручную: `npm run build`, затем пуш в `main` —
  Vercel собирает и раздаёт `dist/` сам (buildCommand/outputDirectory заданы
  в `vercel.json`).

## Как дашборд получает и сохраняет данные (после перехода на редактор карточек)

Данные карточек — не Списки, а `app.option` приложения:

1. Сотрудник открывает пункт меню → Битрикс24 грузит `index.html` в `iframe`
   и передаёт туда токен авторизации POST-запросом. `api/serve.js`
   перехватывает этот POST: если в теле есть `AUTH_ID`/`REFRESH_ID`
   администратора портала, `maybeCaptureServiceToken` (`api/_bitrixAuth.js`)
   меняет их на сервисный токен и сохраняет его в Redis — это нужно один раз,
   дальше он обновляется через `refresh_token`.
2. `index.html` условно подключает SDK Битрикс24
   (`api.bitrix24.com/api/v1/`) — **только если страница открыта внутри
   iframe** (`window.self !== window.top`), иначе при прямом заходе дашборд
   показывает «Автономный режим» на `localStorage`.
3. **Чтение**: `src/bitrix.ts` → `fetchDashboardOption()` вызывает
   `BX24.callMethod('app.option.get', ...)` прямо из браузера — запрос уходит
   не на Vercel, а к родительскому окну (порталу). Не ограничено правами,
   сервер не участвует.
4. **Запись**: `app.option.set` разрешён только администраторам портала,
   поэтому браузер сотрудника шлёт изменения на `POST /api/save-dashboard`
   вместе со своим токеном (`BX24.getAuth()`); функция проверяет токен через
   `profile` и сам пишет в `app.option` сервисным токеном из Redis. Ключ
   опции — `rck_dashboard_v1` (см. `api/save-dashboard.js`, константа
   `OPTION_KEY`); ключ сервисного токена в Redis — `rck:bx-service-token`
   (см. `api/_bitrixAuth.js`) — оба уникальны для РЦК, не пересекаются с
   `iic_dashboard_v1`/`iic:bx-service-token` в infocenter-IIC, даже если оба
   проекта когда-либо окажутся в одном Redis.

Диагностика (не раскрывает сам токен):
**https://\<домен-проекта-на-vercel\>/api/bitrix-status**

## Обязательная настройка на Vercel (один раз, для записи карточек)

Без этого шага дашборд работает, но сохранение в общие данные портала будет
падать с понятной ошибкой в шапке — карточки при этом всё равно сохраняются
локально (`localStorage`) у того, кто их правил.

1. **Storage → Create Database → Redis** (Redis Cloud) → подключить к
   проекту. Storage Type — **RAM only**, план **Free (30 MB)** достаточно
   (хранится один маленький токен, а не данные дашборда — они живут в
   `app.option` Битрикс24). При подключении в поле **Custom Prefix** указать
   `REDIS` — тогда Vercel сам создаст переменную `REDIS_URL`.
2. В **Settings → Environment Variables** проекта добавить:
   - `BITRIX_CLIENT_ID` — «Ключ приложения» локального приложения в Б24
   - `BITRIX_CLIENT_SECRET` — «Секретный ключ» оттуда же
3. Передеплоить проект (если переменные добавлялись после последнего
   деплоя).
4. Попросить администратора портала **один раз открыть приложение** в
   Битрикс24 (полная перезагрузка страницы, не просто переключение вкладки
   браузера) — это момент, когда сервер получает и сохраняет сервисный
   токен. После этого сохранять карточки сможет любой сотрудник.

Если сервисный токен по какой-то причине перестанет обновляться (например,
приложение долго не переоткрывали) — попросить администратора снова открыть
приложение один раз; текущее состояние видно на `/api/bitrix-status`.

## Настройка в Битрикс24

Приложения → Разработчикам → Другое → Локальное приложение:
- Путь обработчика: URL проекта на Vercel
- Права: дополнительный scope не требуется (раньше был нужен `lists` для
  чтения Списков — теперь можно снять, карточки не читают Списки)
- «Использует только API» и BitrixMobile — выключены
- Закрепить пункт меню звёздочкой «В избранное» — новые приложения уходят в
  конец списка «Ещё»
- Скопировать **«Ключ приложения»** (client_id) и **«Секретный ключ»**
  (client_secret) со страницы этого локального приложения — для переменных
  окружения на Vercel, см. выше
