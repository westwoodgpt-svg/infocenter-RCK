# Инфоцентр РЦК — как это устроено

Дашборд для ЦПП Калининградской области (React + Vite + TypeScript + Recharts),
встроен в Битрикс24 как локальное приложение. Развёрнут в июле 2026.

## Что было сделано

**14.07.2026 — сборка, фикс бага, деплой.**

1. Собрали проект (`npm install && npm run build`), интеграция со Списками
   Битрикс24 (`src/App.tsx`, блок `LISTS`, ID 78–87) на тот момент была уже
   проверена и работала.

2. **Починили баг с пустыми графиками.** На вкладках «Качество» и «Персонал»
   часть графиков не рисовалась (высота контейнера — 0, SVG отсутствовал).
   Причина — не анимация вкладок (AnimatePresence), а CSS: обёртки графиков
   имели класс `flex-1` внутри карточки `flex flex-col` без явной высоты
   у родителя. По спецификации flexbox в такой ситуации `height: 100%` у
   `ResponsiveContainer` схлопывается в 0. Убрали `flex-1` из трёх мест
   (`QualityPanel.tsx`, `PersonnelPanel.tsx`), оставив только `h-[...]`.
   Проверено headless-Chromium (Playwright) по всем 5 вкладкам — все 11
   графиков рендерились.

3. Добавили `base: './'` в `vite.config.ts` — пути к `assets/index.js` и
   `assets/index.css` в `dist/index.html` стали относительными (без этого
   Vite ставит абсолютные `/assets/...`, и сборка не открывается не из
   корня домена).

**07.08.2026 — интеграция со Списками удалена, добавлен редактор карточек.**

Автосинхронизация со Списками Битрикс24 (`LISTS`, `RckDashboardData`,
`SecurityPanel`/`QualityPanel`/`ProductionPanel`/`CostsPanel`/`PersonnelPanel`,
`src/data.ts`) полностью удалена и заменена редактируемым конструктором
карточек, перенесённым из [infocenter-IIC](https://github.com/westwoodgpt-svg/infocenter-IIC)
(коммит `646e2f2`) — см. `README.md` про типы карточек и UX. Показатели теперь
вводятся вручную через «Режим редактирования», а не читаются из Списков.

Бэкенд общих данных (сервисный токен администратора для записи в `app.option`
от имени любого сотрудника) реализован под тот же рантайм, на котором уже
хостится РЦК — Cloudflare Workers, а не под Vercel+Redis, как в оригинале ИИЦ
(см. раздел «Хостинг» ниже и «Общие данные для всех пользователей» в README).

## Хостинг: Cloudflare Workers (не Диск Б24, не GitHub Pages)

Перебрали три варианта, прежде чем остановились на рабочем:

- **Диск Битрикс24** — не подходит вообще. Облачный Б24 блокирует загрузку
  HTML-файлов со `<script>` («потенциально опасные конструкции»), а даже
  если бы пропустил — Диск не отдаёт файлы как веб-страницы, относительные
  пути между ними не работают.
- **GitHub Pages** — сборка открывается по прямой ссылке, но отвечает
  `405 Method Not Allowed` на POST. А Битрикс24 открывает локальное
  приложение именно POST-запросом (передаёт токен авторизации). Итог:
  приложение не открылось бы изнутри портала.
- **Cloudflare Workers** — сработал. Финальная схема:
  - `wrangler.jsonc` — конфиг: воркер `worker.js` + статика из `dist/`
    через биндинг `ASSETS`, с `"run_worker_first": true` (иначе Cloudflare
    сначала пытается отдать статику напрямую и всё равно падает на POST).
  - `worker.js` — на `/api/save-dashboard` и `/api/bitrix-status` отвечает
    сам (см. ниже); на любой другой `POST` пытается поймать сервисный токен
    администратора из тела запроса, а затем переигрывает запрос в `GET` и
    отдаёт тот же `index.html`; на `GET` отдаёт статику как есть.
  - Деплой: `npx wrangler deploy` (учётка Cloudflare — westwoodgpt@gmail.com).
  - Боевой URL: **https://infocenterrck.westwoodgpt.workers.dev/**

## Как дашборд получает и сохраняет данные (после перехода на редактор карточек)

Хостинг (Cloudflare) отдаёт статику (`dist/`) и обслуживает два JSON-эндпоинта
из `worker.js`. Данные карточек — не Списки, а `app.option` приложения:

1. Сотрудник открывает пункт меню → Битрикс24 грузит наш `index.html` в
   `iframe` и передаёт туда токен авторизации POST-запросом. `worker.js`
   перехватывает этот POST: если в теле есть `AUTH_ID`/`REFRESH_ID`
   администратора портала, воркер меняет их на сервисный токен и сохраняет
   его в Cloudflare KV (`maybeCaptureServiceToken` в `worker.js`) — это
   нужно один раз, дальше он обновляется через `refresh_token`.
2. `index.html` условно подключает SDK Битрикс24
   (`api.bitrix24.com/api/v1/`) — **только если страница открыта внутри
   iframe** (`window.self !== window.top`), иначе при прямом заходе на
   Cloudflare-URL дашборд показывает «Автономный режим» на `localStorage`.
3. **Чтение**: `src/bitrix.ts` → `fetchDashboardOption()` вызывает
   `BX24.callMethod('app.option.get', ...)` прямо из браузера — запрос уходит
   не на Cloudflare, а к родительскому окну (порталу). Не ограничено правами,
   сервер не участвует.
4. **Запись**: `app.option.set` разрешён только администраторам портала,
   поэтому браузер сотрудника шлёт изменения на `POST /api/save-dashboard`
   вместе со своим токеном (`BX24.getAuth()`); `worker.js` проверяет токен
   через `profile` и сам пишет в `app.option` сервисным токеном из KV. Ключ
   опции — `rck_dashboard_v1` (см. `worker.js`, константа `OPTION_KEY`).

Диагностика (не раскрывает сам токен):
**https://infocenterrck.westwoodgpt.workers.dev/api/bitrix-status**

## Обязательная настройка на Cloudflare (один раз, для записи карточек)

Без этого шага дашборд работает, но сохранение в общие данные портала будет
падать с понятной ошибкой в шапке — карточки при этом всё равно сохраняются
локально (`localStorage`) у того, кто их правил.

1. Создать KV-namespace: `npx wrangler kv namespace create RCK_KV` — команда
   выведет `id`. Вставить его в `wrangler.jsonc` → `kv_namespaces[0].id`
   вместо `REPLACE_WITH_KV_NAMESPACE_ID`.
2. Задать секреты воркера (не переменные окружения — именно секреты, чтобы не
   светились в `wrangler.jsonc`/логах):
   ```bash
   npx wrangler secret put BITRIX_CLIENT_ID
   npx wrangler secret put BITRIX_CLIENT_SECRET
   ```
   Значения — «Ключ приложения» и «Секретный ключ» со страницы локального
   приложения в Битрикс24 (см. «Настройка в Битрикс24» ниже).
3. `npx wrangler deploy`.
4. Попросить администратора портала **один раз открыть приложение** в
   Битрикс24 (полная перезагрузка страницы, не просто переключение вкладки
   браузера) — это момент, когда воркер получает и сохраняет сервисный
   токен в KV. После этого сохранять карточки сможет любой сотрудник.

Если сервисный токен по какой-то причине перестанет обновляться (например,
приложение долго не переоткрывали) — попросить администратора снова открыть
приложение один раз; текущее состояние видно на `/api/bitrix-status`.

## Настройка в Битрикс24

Приложения → Разработчикам → Другое → Локальное приложение:
- Путь обработчика: `https://infocenterrck.westwoodgpt.workers.dev/`
- Права: дополнительный scope не требуется (раньше был нужен `lists` для
  чтения Списков — теперь можно снять, карточки не читают Списки)
- «Использует только API» и BitrixMobile — выключены

В веб-версии портала пункт меню новых приложений уходит в конец списка
(«Ещё» внизу левого меню) — нужно закрепить через звёздочку «В избранное»
или администратору применить общее меню для всех сотрудников.

## Репозиторий

https://github.com/westwoodgpt-svg/infocenter-RCK — ветка `main`.
При изменениях: `npm run build && npx wrangler deploy`.

Ветка `gh-pages` (GitHub Pages) оставлена как публичная витрина
автономного режима — на интеграцию с Б24 не влияет, можно удалить.

`vercel.json`/`api/serve.js` — заготовка под альтернативный хостинг на
Vercel, оставлена как в infocenter-IIC (там, где ИИЦ использует Vercel как
основной хостинг с Redis, здесь это неиспользуемый запасной вариант; боевой
бэкенд карточек — только `worker.js`+KV, описанный выше). Если вариант с
Vercel когда-либо понадобится как основной, `api/save-dashboard.js` и
`api/_bitrixAuth.js` из infocenter-IIC переносятся почти без изменений — их
там ещё нет, но протокол идентичен.
